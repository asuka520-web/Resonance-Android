# v0.7.0 手机核心功能验证

普通版/预览版仍为各自包名，使用固定签名覆盖同一包名的 v0.6.2。旧数据保留，自动换方向默认关闭。

## 先准备真实曲风与候选

1. 在 QQ 音乐播放一首歌，等待 Resonance 自动识别歌名/歌手。必要时展开“核实 / 修改歌曲信息”。
2. 点“查询当前歌曲曲风并核对版本”。此操作将本首歌名和歌手发给 MusicBrainz；不会发送历史、歌词或 QQ 媒体 ID。
3. 根据歌手、专辑、时长、现场/混音备注选对录音，点击“版本相符，读取此录音曲风”。不要为得到标签选择错误版本。
4. 查无结果/无标签应保持未知，不能据此冒充识别成功。保存后退出重进应保留曲风与来源；改歌名/歌手/专辑应让旧对应失效。
5. 对其他歌曲补齐曲风：“补齐本机其他歌曲曲风”可查询之前识别的歌，无须切回播放。至少准备一组同曲风候选与一首其他曲风歌曲。录音标签覆盖不保证，英文标签按来源显示。

## 同曲风推荐

- 播放一首有曲风的歌，点“我想继续听这类歌”。推荐应为其他歌曲，具有共同标签并显示理由；同歌手但无共同曲风不应入选。
- 当前歌、相同 MusicBrainz 录音的其他 ID、最近十次记录中被快跳/中途切走的歌应被排除。
- 目标 70/30 以本机是否有历史记录为准，缺少某组时补足并显示实际数量。“本机无记录”不能当成全局从未听过。
- 缺少锚点标签或其他候选时，应说明缺失条件。此版按曲风相似，尚未理解音色、情绪和节奏。

## 指定播放（优先测试，再开启自动）

1. 查看主面板“公开队列”“媒体 ID 选曲”“队列选曲”。这是 QQ Music 的能力声明，还不代表接受请求。
2. 对一个可请求的推荐点“在 QQ 音乐播放此推荐”。核对 QQ 音乐实际正在播放的歌曲。
3. Resonance 只有观察到目标 **MEDIA_ID** 正在播放，跨两次且至少一秒的观察，才应显示“已确认”。变成另一首、仅暂停在目标、接口无报错，都不算成功。
4. 未响应应约十秒报超时；无能力应禁用按钮并说明原因。不应重复请求或用普通“下一首”追逐目标。
5. 推荐请求产生的歌曲切换不应增加你的快速跳过次数。断开监听/更换会话应取消待确认请求。

若 QQ 音乐没有公开指定播放能力，或忽略请求，保留推荐结果并记录这个限制；不能判定自动换风格已通过。

## 四次快跳与自动换方向

1. 先为将要跳过的四首歌曲查好标签（快跳太快可能来不及自动识别）。四首至少三首共有某一曲风，另准备至少一首不含该曲风的候选。
2. 先保持自动开关关闭，连续四首各播放少于 15 秒后手动切歌。查看自动生成的“换方向”建议、避开曲风及候选曲风，不应实际干预。
3. 缺任一首曲风应说明资料不足；四首风格混杂应说明无法推断共同方向。补资料后可点“重看最近四次快跳的换方向建议”，这不会自动播放。
4. 指定播放验证通过后再开“允许四次快跳后自动尝试换方向”。等待上次触发满 120 秒，重新完成四次快跳。符合条件时仅发送一个候选请求，并等待实际播放确认；暂停状态不自动恢复播放。
5. 冷却内不重复分析/控制。失败不循环，自动控制引起的切换不作为用户负反馈。

## 本机检查与外部来源

新增单元测试覆盖曲风排序、真实候选配比、资料缺失/混杂、播放确认/超时、曲库解析与身份变化。编译和测试通过不替代上述 QQ 音乐真机验收。

- [MusicBrainz 公开查询文档](https://musicbrainz.org/doc/MusicBrainz_API)
- [查询速率与应用身份要求](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting)：客户端全局串行、请求起点间隔至少 1.1 秒，明确 User-Agent，无后台批量上报。
- [Android 公开媒体控制](https://developer.android.com/reference/android/media/session/MediaController.TransportControls)

实测公开数据：`Get Lucky` / `Daft Punk` 可返回多个录音；`0347d102-b653-4c6c-a0b2-cc9a58c5c585` 返回 `funk`，`604b0c12-31a3-4219-8965-70051e2289db` 未返回曲风。此例证明必须核对版本并允许未知，不是手机曲库的预置数据。

JSON 维持 schemaVersion 3，并附加 trackFeatures。原 PC 验证器可继续读取听歌记录；PC 不参与曲风查询/手机播放执行，重新导出可能不带新增曲风字段，请保留手机原始导出文件。

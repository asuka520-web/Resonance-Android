# v0.6.2 自动获取歌曲信息

2026-11-17，用户提供真机截图并确认多曲目观察通过：在其 QQ 音乐版本上，ARTIST
为稳定的“歌名-歌手”复合字段；TITLE 含动态歌词/制作信息，DISPLAY_TITLE 为空。

实现只使用经验证的 ARTIST 复合格式。要求稳定媒体 ID、唯一且两侧非空的分隔符，
拒绝多连字符歧义、控制字符及明显的词曲制作字段。至少三次观察、跨度 2.4 秒后
才自动缓存。相同 ID 下歌名/歌手随后变化时停用该自动记录并要求人工核实。
TITLE 从未进入解析器，不会成为自动歌名或歌曲身份。

自动信息单独保存在 `resonance_auto_song_info`，来源为 `qq-session-artist`。
既有 `resonance_song_info` 人工信息及旧 `resonance_song_labels` 标签始终优先，
不被自动写入覆盖。自动写入不会覆盖用户正在编辑的内容。
用户仍可点击“确认并保存歌曲信息”将校正内容保存为人工信息。

JSON 继续使用 schemaVersion 3，songInfo 中保留来源；历史及偏好展示优先使用人工
信息，再使用有效的自动缓存。未知格式继续显示媒体 ID 并允许人工填写。

验收：找一首尚未人工标注的歌曲，播放约 4 秒，确认首页显示“QQ 音乐自动读取”，
歌名/歌手/专辑正确且无需点击保存。切走再回来应恢复缓存。手动修改并保存后，
后续监听不能改回。导出 JSON 的自动记录 source 应为 qq-session-artist，人工确认
记录为 user-confirmed。不同客户端的格式不能假设相同。

该功能只解决歌曲信息自动读取，不提供风格分类、查找新歌或指定歌曲播放。

## 旧云端签名的升级处理

检查旧工作流日志发现 `~/.android/debug.keystore` 缓存路径没有实际文件，缓存未保存。
旧构建的私钥不在该缓存中，不能承诺新包能覆盖旧云端安装。
现改为显式的 RESONANCE_DEBUG_KEYSTORE 路径和 v2 缓存，并在构建前确保密钥存在。
缓存仍不是永久签名备份；正式发布前需要持久托管的发布密钥。

工作流同时生成 `Resonance-preview-debug.apk`（com.resonance.app.preview，启动器名称
“Resonance 预览版”），用于不卸载旧版的并行验证。两应用数据隔离，预览版不会自动
迁移旧历史。用户应在预览版单独启用通知读取权限，测试未人工标注的歌曲。

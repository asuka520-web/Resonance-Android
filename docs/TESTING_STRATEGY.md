# 手机主产品，PC 验证台

Android 负责实际的 QQ 音乐监听、历史、确认信息和偏好展示。
PC 用来检查产品交互、回放手机数据、复现规则问题。手机功能优先；PC 不另建一套推荐产品路线。

## 三层验证

1. **手机内核在电脑上运行**：`BehaviorTracker.kt` 没有 Android 平台依赖，
   Android JVM 测试直接执行手机使用的判断代码。
2. **两端共用规则样本**：`test-fixtures/listening-contract.json` 给出人工定义的
   边界和预期结果，两端分别执行分类、换歌序列和评分核对。
   Kotlin 与 Python 仍是独立实现，共用样本能发现覆盖范围内的差异，不能证明所有输入等价。
3. **手机实际运行验收**：通知权限、MediaSession 字段语义、后台/锁屏、系统杀进程、
   耗电和重连只能在 Android 手机或模拟器验收，PC 不替代这一步。

## 本轮 v0.6.1

- 抽出手机的纯 Kotlin 行为判断器，保留原分类阈值和历史结构。
- 暂停、会话丢失、监听断开、读取错误、稳定 ID 丢失时暂停推断。
- 新歌曲不沿用旧歌曲的时长和进度。
- 第一组四次快跳不受开机后前 120 秒限制；后续触发仍冷却 120 秒。
- Android 进度推算不超过时长，并处理未知位置及无效更新时间/速度。
- 给历史快照增加运行期修订号，解决 500 条上限时统计数量相同但内容变化未刷新的问题。
- SharedPreferences 的既有键、用户确认信息和设置不变；导出继续为 schemaVersion 3，增加 platform=android 标记。

## PC 回放手机记录

在手机导出 JSON 后，将文件复制到电脑，在 PC 点击 **回放手机 JSON**。

- 只读打开，不导入真实库或模拟库。
- 可以上一条、下一条、查看全部或自动逐条回放。
- 每一步显示到当前为止的 20/500 条统计和单曲分数。
- 将手机记录的类别与相同进度/时长下的分类结果对照，不一致时标记但不改写。
- JSON 包含的是已经记录的行为，不含逐秒会话；回放不能验证当时的暂停、通知权限或后台状态。
- 旧版记录可能保留历史误判，修复不会删除或重分类用户旧记录。

## 真机验收顺序

先确认签名可以覆盖升级，备份 JSON，避免卸载造成数据丢失。

1. 同一首歌播放且歌词变化：不产生假切歌。
2. 连续快跳四首：产生四条记录及一次触发，后续遵循冷却。
3. 暂停后切歌：不把暂停的上一首误记为快跳。
4. QQ 音乐退出/恢复或权限断开/恢复：不串用旧进度。
5. 切到时长/ID 暂缺的歌曲：保持未知，不借用旧字段。
6. 锁屏和后台听歌后检查历史，核对旧数据、人工标签和设置仍保留。
7. 导出 JSON 到 PC 只读回放，核对计数、评分及有无规则差异。

完成这轮手机数据验收后，再以经过确认的歌手信息做偏好画像。
推荐曲库、歌曲查询和自动播放仍需可验证且允许使用的集成来源。

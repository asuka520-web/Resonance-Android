# Resonance 核心需求与实现路线

以用户在 2026-11-17 当前聊天中重新明确的需求为准。本文是需求与技术路线，**不是已完成功能声明**。

## 主产品与两条主线

Android 手机为实际使用端，QQ 音乐为当前目标播放器。PC 负责模型实验、效果预览、规则复现和数据检查。

1. **自动换风格**：连续 4 次快速跳过后，判断当前方向不合适，选择不同风格方向的可播放歌曲并切换；保持 120 秒冷却。不能以不断调用“下一首”冒充按风格切换。
2. **当前感觉的相似推荐**：以当前明确喜欢的歌曲、用户选定的歌曲或最近正反馈为锚点，推荐声音/情绪/节奏接近的歌曲。不能把“同一歌手”或单曲分数排行等同于相似音乐。

原计划的 70% 熟悉偏好、30% 陌生歌曲探索是候选策略目标。陌生歌曲可以属于熟悉的风格，不等同于 30% 随机切换曲风。

## 必须连通的能力

歌曲身份 → 歌曲特征 → 可播放候选曲库 → 当前意图 → 策略排序 → 播放请求 → 实际播放结果确认。

当前只完成基础行为记录、人工元数据确认、单曲评分，以及验证工具。上述推荐闭环尚未完成。

### 1. 歌曲身份

- 将媒体会话中的稳定 ID 当作观察身份，不假设它与目录服务 songId/songMid 相同。
- 检查 QQ 音乐实际提供的字段及变化，TITLE 不单独作为歌名或切歌依据。
- 有允许使用且适配本应用的歌曲查询服务后，建立播放端 ID 与目录 ID 的映射。
- 用歌名、歌手、专辑、时长和版本核对匹配，保存来源和置信度；模糊匹配不能自动认定。
- 音频指纹是可选补充，前提是能取得允许分析的音频；当前没有这项输入能力。

验收：不同歌曲、翻唱/现场/混音等版本能正确区分；未知时明确返回未知，不能保存歌词为歌名。

### 2. 音乐特征与风格

- 使用多标签特征：曲风、情绪、节奏、能量、人声/纯音乐、语种。
- 优先接入适配应用的曲库标签；用户校正作为补充，不作为整个系统的唯一标签来源。
- 能取得允许分析的音频后，可评估 Essentia 等模型，离线生成风格概率和音频向量，手机缓存特征并排序。
- PC 适合做模型效果评估和特征预计算；需要覆盖候选曲库，不能只分析当前一首歌。
- 每个特征保留来源、置信度和模型版本；未知特征不填成 0 或默认某种风格。
- 不能仅由歌手、标题、歌词或跳过行为断言歌曲曲风。

验收：在人工标注样本上报告分类准确情况、错误例子与覆盖率；不是只展示一个模型标签。

### 3. 当前意图与推荐

- 长期偏好来自累计正负反馈；当前意图更重视本次会话和最近正反馈。
- 相似模式的锚点不能自动选为刚被连续跳过的歌曲；优先用户明确选择或最近喜欢的歌曲。
- 四次快跳后，降低近期被拒绝歌曲共同特征的短期权重，增加其他方向探索；若这些歌曲风格混杂，不强行解释成讨厌某一曲风。
- 快跳对长期画像的影响应保守且可衰减，不能四次跳过就永久屏蔽风格。
- 候选排序考虑音乐特征相似度、短期意图、长期偏好、重复惩罚和探索。
- 没有可靠身份、特征或可播放候选时，显示具体缺失条件，不返回虚构的风格切换结果。

验收：可查看每次的锚点、跳过信号、候选特征、推荐理由，以及切换前后的风格差异。

### 4. 播放执行与关键可行性验证

Android `MediaController.TransportControls` 提供 `skipToNext`、`playFromMediaId`、`playFromSearch` 等请求入口。
这不证明 QQ 音乐接受任意歌曲 ID，也不证明能修改它的推荐队列。

优先在手机验证：

1. QQ 音乐公开的实际播放能力、队列和媒体信息是什么。
2. 能否请求一首确定的目标歌曲，尤其是当前队列之外的目标。
3. 发出请求后能否根据新会话信息确认播放的确实是该目标；仅 ID 变化不算成功。
4. 不支持或超时时是否明确报告，并避免循环跳歌或重复干预。

若不支持指定歌曲播放，需验证适配的官方接入或其他允许的调用路径；不能宣称“连续跳过后自动换风格”已实现。
更换播放器、内置音源等属于产品范围决策，不能自行替换 QQ 音乐主目标。

## 开发与验收优先级

1. **先验证闭环接入可行性**：歌曲目录/标签来源、指定歌曲播放及播放结果确认。
2. **建立真实可用的候选样本曲库**：有正确身份、风格特征和可播放引用；合成样本只作测试，不能冒充真实识别。
3. **做两条核心策略**：相似推荐、连续跳过后的方向切换，并在手机实现可见的推荐结果及解释。
4. **接入自动执行并验收**：在手机看到“触发 → 推荐 → 实际目标歌曲播放”的完整链条。

歌手画像、短长期变化、本地重听推荐继续作为基础模块，但不单独作为两条核心需求完成的依据。
PC 统计或回放通过，也不作为手机端推荐与播放执行通过的依据。

## 已核查的资料

- [Android 媒体控制请求](https://developer.android.com/reference/android/media/session/MediaController.TransportControls)
- [腾讯连连音乐服务](https://cloud.tencent.com/document/product/1081/67456)：是特定 H5/设备接入环境，尚未验证适用于本应用。
- [MusicBrainz 查询字段](https://musicbrainz.org/doc/Indexed_Search_Syntax)：可用于候选元数据核对，尚未评估实际曲库覆盖率，不提供 QQ 音乐播放权。
- [Essentia 音频模型](https://essentia.upf.edu/models.html)：包含风格与情绪等模型，需要音频输入；模型许可也需适配实际使用。
- [Android 音频捕获条件](https://developer.android.com/media/platform/av-capture)：需要用户许可并受播放应用捕获策略约束，不能默认可读取 QQ 音乐音频。

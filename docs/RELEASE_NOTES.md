## Android v0.11.0：发现栏目、可选等待与换来源补曲风

- 新增“发现”栏目：浏览收藏外歌曲、推荐来源，搜索歌曲/歌手/专辑，按曲风和本机无记录筛选；支持播放当前结果前 100 首或从任意歌曲起播放一个窗口，保持列表顺序。
- 排序参考真实近期正反馈，分散歌手，过滤近期跳过、已收藏及已知同录音重复歌曲。QQ 歌曲关联不等同于 QQ 账号私人推荐，也不冒充声音/情绪识别。
- 按用户反馈取消原生播放器默认 120 秒等待：每满四次有效快跳即可再次分析方向；“我的”可选不额外等待、15/30/60/120 秒，下一次切歌立即应用。自动换歌仍不记为用户快跳，旧版外部监听规则保留。
- 收藏页显示“重试未取得曲风”“换来源补齐”两个按钮，初始分析中也能安排重试。后者直接查询补充来源；普通查询在 QQ 空结果或错误时亦可回退。
- 补充资料继续严格匹配真实录音；开启状态、取消操作、连续失败暂停均保留。缺失或查询失败不擦除已有正标签，不保证所有未知曲风都能补齐。

按 [v0.11.0 手机测试清单](https://github.com/asuka520-web/Resonance-Android/blob/main/docs/DISCOVERY_BROWSER_TEST.md) 验证。沿用固定签名覆盖安装，请从手机文件管理打开 APK，无须卸载旧版。

## Android v0.10.0：缺失曲风重试、自动发现新歌与推荐队列

- 收藏曲风区分已取得、等待查询、查询失败待重试、来源暂无资料；兼容已有缓存并保留正标签。增加批量重试缺失歌曲和单独筛选入口，无需逐首填写。
- 从不同已知曲风及正反馈收藏自动选择种子，串行获取 QQ 相关歌曲候选；当前播放歌曲也可扩展候选。首页显示收藏外候选数量与“发现更多”，成功资料缓存、按账号保存，失败保留已有候选。
- 没有曲风的歌曲可使用 QQ 明确返回的直接相关候选参与相似推荐，标明关系依据，不伪造曲风；四次快跳换方向继续严格要求已知标签。
- 增加“播放这批”，点击推荐歌曲从该批对应位置播放，保持推荐队列，不重新接回收藏顺序。列表显示多标签摘要，展开播放页显示全部标签。
- 音源仍由 QQ 按账号权益提供，音频缓存仍为 100 MiB；新增发现只读元数据，不预下载歌曲。声音/情绪模型不在本轮实现范围。

手机验收见 [v0.10.0 测试清单](https://github.com/asuka520-web/Resonance-Android/blob/main/docs/DISCOVERY_RELEASE_TEST.md)。未知曲风不保证能被补齐，推荐数量取决于真实返回候选和音源可用性。

## Android v0.9.0：后台播放、自动收藏曲风与全新页面

- 播放迁入独立 MediaSessionService：界面退出不再主动释放音源，支持系统媒体通知、锁屏/耳机控制；标准音质按需读取，音频缓存采用 100 MiB 淘汰上限并按账号隔离。
- 已登录时自动分页同步 QQ 收藏，每次最多 100 页；保留缓存、同步进度及异常说明，避免只读取首批 50 首或重复分页死循环。
- 按准确 QQ MID 自动读取单曲流派，无需逐首核对。QQ 缺失标签时后台补充查询，结果不唯一保持未知。资料来源与在线补全开关收进设置，主页面不再展示接口或逐首标注流程。
- “继续这个感觉”连接收藏与真实 QQ 相关歌曲候选，按曲风与真实反馈排序，区分熟悉候选和探索候选；70/30 为可用候选策略目标，缺少候选不伪造配比。
- 四次有效快跳后，在资料足够且存在其他方向候选时切换一批不同曲风歌曲，保留 120 秒冷却；系统替换不作为用户负反馈。
- 反馈改用播放器的明确事件和实际听歌时间；拖动进度、暂停、加载失败、试听片段不制造基本听完或快跳偏好。
- 重做“为你 / 收藏 / 我的”、封面与曲风标签、迷你播放器和展开播放页，增加统一深色主题与共鸣图标。旧版记录入口仍保留。

**手机验收**：v0.8.0 的账号接入已由用户确认通过；本轮新增后台播放、锁屏控制和持续队列仍需按 [测试清单](https://github.com/asuka520-web/Resonance-Android/blob/main/docs/BACKGROUND_RELEASE_TEST.md) 在手机验证。
当前曲风来自曲库标签，尚不等于独立音频/情绪分类模型。收藏分析只读取元数据，不下载整个收藏音频，也不经过自建音乐中转服务器。

## 保留 v0.8.0 的 QQ 账号接入

- 首页改为 QQ 账号播放器验证入口，保留旧监听页面与已有数据。
- 在共鸣内打开 QQ 音乐官方网页登录，区分网页会话、播放票据与实际接入结果；登录凭据只在本机 WebView 保存，不进入历史导出，WebView 数据排除备份。
- 增加读取“我的喜欢”、自建歌单及歌单首批歌曲的第三方 QQ 网页协议适配，每批最多 50 项。接口来源与限制见新方向文档。
- 增加共鸣内原生前台单曲播放、暂停/继续及真实进度确认，严格核对请求歌曲 MID，明显短于完整歌曲的音源标明可能为试听片段。
- 退出登录清除共鸣内网页会话；已有听歌记录、歌曲标注和固定签名保留。

**这是一版接入验证，不代表 QQ 手机登录、曲库、完整歌曲播放已通过真机验收。** 本轮不接自动推荐、后台播放或完整队列；先通过同一账号“登录 → 实际歌曲列表 → 共鸣内实际播放一首”的关卡，再继续两条推荐主功能。

安装后先使用首页登录入口，完成官方登录后返回，点“读取我的喜欢”或“读取我的自建歌单”，再选择一首歌点击“在共鸣播放”。反馈页面提示及实际是否有声音即可，不要发送登录 Cookie 或账号票据。

## 保留 v0.7.0 的旧监听功能

- 增加真实公开曲风查询：点击后向 MusicBrainz 发送所选歌名和歌手，核对录音版本后读取录音级曲风；不上传历史或歌词。未收录或无标签时保持未知。
- “我想继续听这类歌”：按已核对曲风重合、近期/长期正反馈及重复惩罚，从本机已识别曲库推荐其他歌曲，展示理由。
- 连续四次快跳后分析共同曲风；只有至少三首共有标签且四首资料齐全时才选择其他方向，保持 120 秒冷却。
- 候选目标为 70% 本机有记录 / 30% 本机尚无记录；不足时展示实际数量，不虚构陌生曲库。
- 增加公开队列与选曲能力读取、目标选曲请求及实际播放确认。准确目标 ID 必须持续播放并跨越两次轮询，10 秒未确认即报超时，不循环跳歌。
- 新自动播放开关默认关闭，旧模式设置不会偷偷开启控制；推荐操作产生的切换不记作你的负反馈。
- 保留旧记录、标注和签名；JSON schemaVersion 仍为 3，新增可选 trackFeatures 字段。

**范围与待验收**：推荐只覆盖本机已识别且有录音曲风的歌曲。尚无全量 QQ 目录、音频/情绪/节奏识别；QQ 音乐是否接受指定播放请求需在手机上验证，界面不会把发出请求称为播放成功。

## 安装与更新

- `Resonance-latest-debug.apk`：普通版，包名 com.resonance.app。
- `Resonance-preview-debug.apk`：可并行安装的“Resonance 预览版”，包名 com.resonance.app.preview。
- 预览版可与旧版共存，数据分开保存，需要单独开启通知读取权限，不会自动迁移旧记录。

当前 v0.6.2 及后续构建固定使用同一 Android 签名，已迁移至 GitHub 加密 Secret，不再依赖临时缓存。
构建会核对公开证书指纹，缺少或不匹配就停止打包，不自动生成新签名。
未来同一包名、相同签名且版本号不降低的 APK 可继续覆盖更新。

早期云端构建使用了未保存的其他签名，不能靠统一新签名补救其覆盖升级。
如果普通版提示签名冲突，不要清数据或卸载旧版；先使用并行预览版验证。

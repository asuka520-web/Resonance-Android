# v0.13.0 手机验收

用文件管理打开普通版 APK 覆盖旧版，保留登录、收藏、曲风及历史；不要卸载。预览版仍是独立数据。

1. **确实换歌**：选择随机，正常播放每首几秒后手动下一首，连续四次有效快跳。确认目标有声音且进度推进，然后看“已换曲风 · 歌名”或资料不足时的“已换一批 · 歌名”。名字应与当前歌一致；前者才说明有避开共同标签的依据。提示约四秒淡出、可点击下方页面。后台不弹跨应用浮层。
2. **换向记录**：“我的”或展开播放器点“最近换向记录”，核对目标歌名、时间、结果、依据及当时分数。尝试失败、30 秒未确认、试听不记为成功；确认前手动切走记取消。没有候选时明确未切换，不伪造一条成功记录。应用重开不能把未完成尝试变成成功。
3. **所有分数**：“为你 → 调整这次选歌 → 标签分数”，全部已有标签包含 0 分。听完 +2、中途切 -1、有效快跳 -3，多标签分摊。近期取 20 条，长期最多 500 条并归一到 20 条，再按 70/30 综合；近期记录也在长期内。综合参与排序，手动想听/避开优先、四连跳另按共同标签避开。这是参考分，不能证明已识别情绪。
4. **随机和续播**：展开播放器选“收藏＋发现”，队列应覆盖实际已载入的曲库（上限 6000 条元数据），而非十首推荐。可改仅收藏或当前这批，当前歌曲继续播放。随机在所选范围打乱、列表循环回到该范围，单曲循环只重复当前歌；手动下一首仍可跳。抽“惊喜一首”后下一首有其他候选，若曲库/筛选实际仅一首则无法凭空续播。
5. **QQ 收藏**：找一首未喜欢的歌曲，打开详情或展开播放器，点“收藏到 QQ 我喜欢”。只有服务端读回确认后才更新；打开官方 QQ 音乐的我喜欢核对，接着在共鸣取消再核对。授权过期或离线应提示失败/未确认，不假成功、不自动重复写入。不确定时按钮先刷新状态，不再次修改。开发机未持有真实账号，写入端到端必须以此项真机结果为准。
6. **细分标签**：收藏页“补充细分曲风”对已有一个标签的歌曲补查，也可在详情只查这一首。默认在线补全开启时，每次启动最多自动处理 20 首符合缓存期限的单标签收藏。严格匹配歌名、歌手、专辑、时长、唯一录音；有更细标签才合并，并列来源。重复结果仍一个标签，无匹配、错误和限流保留原标签；资料缺失无法保证补齐。30 天正结果、7 天无额外资料、15 分钟网络失败缓存；手动可重查，连续三次失败暂停。关闭在线补全不发后续查询。

## 来源与验证边界

QQ 收藏使用独立适配的网页协议：SongFavRead/IsSongFanByMid、PlaylistDetailWrite/AddSonglist/DelSonglist（dirId 201），新鲜歌曲数字 ID 与 type，zzc/ag-1 加密写入，响应码及 retCode 严格检查并读回。参考 [QQMusicApi](https://github.com/L-1124/QQMusicApi)、[simple-music 的协议适配](https://github.com/Yyyangshenghao/simple-music/tree/main/server/lib)。不是官方 Android SDK，可能受网页会话与服务变化影响；不绕过账号权限。

协议签名与加密互操作参考 [qmweb-sign 的固定版本](https://github.com/jixunmoe/qmweb-sign/tree/15305a3cc39f80eb1646ab2bae46468231765736)，MIT / Copyright (c) 2024 Jixun Wu，完整许可在 third_party/qmweb-sign-LICENSE.txt 及 APK assets/third_party。业务逻辑独立实现。测试覆盖密码固定向量、严格返回值、身份不符、一次写入/读回、账号取消、队列范围、分数、换批、补充合并及真实原生页面；截图是虚构曲库。没有开发机真实账号写入、没有用户曲库新增标签覆盖率或中文情绪模型准确率结论。

# v0.9.0 手机验收：后台播放、自动收藏分析与新界面

用户已确认 v0.8.0 QQ 账号接入通过。本轮沿用同一网页登录会话和签名，旧记录保留。QQ 官方 App 无须承担共鸣的播放队列；音源由手机直接读取，共鸣后台播放。

## 安装和页面

- 使用与当前安装相同包名的普通版或预览版覆盖。登录会话通常保留，必要时在“我的”更新授权。
- 首页为“为你 / 收藏 / 我的”，播放器缩在底部；点击迷你播放器展开封面、进度和控制。
- 检查收藏搜索、曲风筛选、小屏滚动、长歌名与暂停/继续。旧监听与历史在“我的 → 旧版监听与记录”。

## 自动收藏与曲风

1. 已登录时自动同步收藏并分页读取，不能只停在首批 50 首。核对与 QQ 收藏数量大体一致（删除、重复或接口权限可能影响）。本轮最多 100 页，达到上限或分页异常会明确提示，保留已读资料。
2. 无须逐首填写或核对。首先按准确歌曲 MID 读 QQ 单曲详情的 `info.genre.content[].value`；不把歌手流派或数字代码默认映射成单曲风格。
3. 查看“曲风资料”和覆盖率逐步增加。覆盖率表示取得标签的比例，不是分类准确率。未取得、网络失败、来源缺失时保持未知。
4. QQ 成功返回但无曲风时，才使用后台补充资料。MusicBrainz 严格核对歌名、主歌手、专辑、时长及版本，候选不唯一不自动采用。日常页面不显示服务名；“我的 → 资料来源与隐私”可查看来源、关闭在线补全。
5. 退出重开应保留已同步收藏和资料，换账号不应混入上个账号的收藏/历史。正标签缓存 30 天、无标签 7 天，失败结果短暂缓存，避免反复请求。

公开实测：2026-11-17，QQ 数字歌曲 5293866 的详情返回「特别的人」、MID `003cSLOO35W3yP`，单曲流派为 `Pop`。同一歌曲的 QQ 相似候选接口返回真实歌曲条目。本例仅证明接口路径和结构可用，不作为全曲库覆盖率或分类准确率报告。

## 后台和系统控制

1. 从收藏选歌，确认有声音且进度推进，然后返回桌面、打开普通非音频应用、锁屏两分钟。音乐应继续。
2. 用通知栏/锁屏暂停、继续、上一首、下一首。拔下有线耳机或其他应用取得音频焦点时，应按系统规则暂停/处理。
3. 从最近任务移除界面，正在播放的媒体服务应继续；系统主动强行停止应用不在此承诺内。
4. 回到共鸣，迷你播放器与进度应对应当前实际歌曲，不能重置播放或出现双重音源。
5. 退出 QQ 账号应停止并清空当前队列；新账号不能继续使用前一账号的播放会话。错误音源不循环跳歌，不将接口返回视为实际播放成功。

## 推荐和四次快跳

- 先等待一些收藏取得标签。点击当前歌的“继续这个感觉”，应以该歌为锚点，候选来自收藏及 QQ 返回的相关歌曲，并进一步按已知曲风和真实反馈排序。
- 收藏算熟悉候选；不在收藏且本机无听歌记录的才进入探索组。目标 70/30，缺少某组时显示实际数量，不虚构陌生歌。
- 人工连续四次跳过**已开始播放**且实际听了不足 15 秒的歌曲，触发方向分析；120 秒内不重复干预。若四首至少三首有共同曲风且资料齐全，尝试播放其他方向的真实候选。
- 缺标签、风格混杂、无目标时给出原因，不用反复普通“下一首”追逐目标。自动切换、加载失败、暂停后很久才换曲和试听片段，不应被记成新的负反馈。
- 拖动进度到结尾不应制造“基本听完”。自然结束也根据实际听过的时间判断。

## 流量与范围

音频默认请求标准压缩音质，按需读取，缓冲约 15–30 秒；只缓存已经播放/缓冲的内容，音频磁盘缓存采用 100 MiB 淘汰上限，按账号隔离。收藏分析只取元数据，不批量下载整库音频，也不经过自建音乐中转服务器。

当前推荐依据是曲库曲风与听歌反馈；未声称完成独立的声音、情绪、能量或 BPM 模型分析。首次整理大曲库需要时间；进程被系统终止后，已缓存资料保留，下次打开继续。

本地 Android 渲染测试使用虚构测试数据并生成截图；它验证页面布局和选择身份，不替代本清单中的真机音频、锁屏与耳机验收。

# v0.15.0 手机验收

从文件管理打开普通版 APK 覆盖更新，不卸载。

1. **动态随机**：播放模式选随机，查看当前标签分数。选择某首歌的“多来这种”，勾选实际想多听的标签确认，再看分数变化和后续播放。高分提高后续出现概率，不保证下一首；一首歌有多个曲风时取平均综合分，未知 / 0 分保持中性。分数先限制到 ±6，权重 exp(0.28×分数)，用无放回加权排列；每次有效反馈后重排尚未播放部分，避免只播放高分的几首。
2. **连续播放**：正在播放时主动反馈、补充标签或清分，当前歌曲与进度应保持，上一首仍能回到本轮已走过的前一首，再下一首返回。范围仍可选收藏＋发现 / 仅收藏 / 当前这批。范围改变允许移除不符合条件的历史项；新一轮会重新随机。跨循环边界的上一首遵循新一轮原生排列，暂不提供完整跨轮播放轨迹。
3. **与换向区别**：四连跳仍独立做共同标签避开与目标确认，成功才出淡入提示。每次普通随机权重更新不会弹“已换曲风”，也不会制造快跳记录。
4. **主动反馈**：展开播放页和歌曲详情可选“多来这种 / 暂时少放”，选择部分或全部曲风再确认；只有“流行”等一个标签时会说明影响该类全部歌曲。无曲风不能假反馈。主动分每次 ±2、最多 ±6，账号内保存，在分数详情显示；听歌历史、陪伴时长及 QQ“我喜欢”不改变。清分后主动与被动分均归零。
5. **标签补充**：自动补查全部到期单标签收藏，不再只查 20 首；也可手动“补充细分曲风”重查无标签 / 单标签收藏。按来源限速、缓存续查、连续三次失败暂停，关闭在线补全不发后续请求。收藏页看多曲风 / 听感线索覆盖数量，详情看完整来源。当前音频不下载、不上传。
6. **曲风与线索**：流行和 pop 等同义词合并，不算两个标签。MusicBrainz 严格匹配到同一录音后，可单独取得至少 2 票且在允许词表内的情绪 / 乐器标注；非曲风标注不混进曲风列表、分数或换向证据，未取得则没有该区域。社区数据并不等于声音模型分析，仍可能有误标。
7. **文案**：日常入口使用“相似推荐”“随心听 · 惊喜一首”；错误、权限、清分等文字保持明确。

公开实测：读取 recording `0347d102-b653-4c6c-a0b2-cc9a58c5c585` 的 `inc=genres+tags`，返回 funk 一票与 happy 一票，后者低于门槛，不导入。这证明接口可读，不证明用户收藏多标签覆盖率。依据 [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API)、[社区标签](https://musicbrainz.org/doc/Folksonomy_Tagging)。使用已固定的 Media3 1.6.1 `ExoPlayer.setShuffleOrder` 与 `ShuffleOrder.DefaultShuffleOrder`；动态排列自主实现，未复制第三方推荐算法。

自动化验证权重概率分布、中性探索、每轮不重复、分数更新后的历史前缀、原生播放器当前进度 / 上一首、主动反馈独立持久化 / 清除、整库补查续查、严格录音线索 / 票数 / 同义词及页面流程。截图用虚构曲库。未完成的声音识别及更多来源列在 ROADMAP.md。
